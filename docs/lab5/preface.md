# Предисловие Kotlin

## Packages — пакеты

По мере роста программы количество файлов и классов увеличивается.
Если хранить весь код в одном месте, проект становится сложнее читать,
поддерживать и развивать.

Для организации кода в **Kotlin** используются пакеты (`package`).
Пакет позволяет логически группировать классы, функции, свойства и
другие объявления.

Например, приложение может иметь следующую структуру:

```mermaid
treeView-beta
    my-project/
        src/main/kotlin/
            org/example/
                Main.kt
                User.kt
                Calculator.kt
```

В файле `User.kt` можно объявить пакет:

```kotlin
package org.example

class User(
    val name: String
)
```

Теперь класс `User` принадлежит пакету `org.example`.

Пакет определяет полное имя класса. В данном случае оно выглядит так:

```text
org.example.User
```

Это имя называется полным квалифицированным именем класса (`fully qualified name`).

### Зачем нужны пакеты?

Пакеты помогают:

* группировать связанные классы;
* избегать конфликтов имён;
* разделять код по областям ответственности;
* упрощать навигацию по проекту;
* делать архитектуру приложения понятнее.

Например, в небольшом приложении можно выделить следующие пакеты:

```mermaid
treeView-beta
org.example
├── model/
│   └── User.kt
├── service/
│   └── UserService.kt
├── repository/
│   └── UserRepository.kt
└── app/
└── Main.kt
```

Здесь `model/` содержит модели данных, `service/` — бизнес-логику,
`repository/` — код доступа к данным, а `app/` — код приложения.

Это лишь один из вариантов организации проекта. Конкретная структура
зависит от его назначения и сложности.

> **Kotlin** не требует, чтобы физический путь к файлу строго
> соответствовал объявленному пакету. Однако рекомендуется поддерживать
> соответствие между пакетами и каталогами, поскольку это облегчает работу
> с проектом.

Например, для пакета `org.example.model` обычно используется каталог:

```text
src/main/kotlin/org/example/model/
```

## Imports — импорты

Если класс или другая сущность объявлены в другом пакете,
для обращения к ним обычно используется `import`.

Допустим, существует файл `User.kt`:

```kotlin
package org.example.model

class User(
    val name: String
)
```

В другом файле можно использовать этот класс:

```kotlin
package org.example.app

import org.example.model.User

fun main() {
    val user = User("Alex")

    println(user.name)
}
```

Директива

```text
import org.example.model.User
```

позволяет обращаться к классу `User` по короткому имени, не
указывая каждый раз его полный путь.

> Конечно, если очень хочется, или у вас имеются одинаковые имена классов,
> то необходимо обращаться к классу `User` по полному пути. Например:
>
> ```kotlin
> package org.example.app
> 
> fun main() {
>     val user = org.example.model.User("Alex")
> 
>     println(user.name)
> }
> ```

### Что можно импортировать?

В **Kotlin** можно импортировать:

* классы и интерфейсы;
* функции;
* свойства;
* объекты;
* перечисления (`enum`);
* отдельные элементы других объявлений, если они доступны для импорта.

Также поддерживается импорт всех доступных объявлений верхнего уровня из пакета:

```text
import org.example.model.*
```

Однако обычно лучше использовать явные импорты.

### Импорты и зависимости — не одно и то же

Важно различать два понятия.

- **Импорт** (`import`) — возможность обратиться к объявлению в исходном коде по имени.

- **Зависимость** (`dependency`) — библиотека или другой компонент, который
  подключается к проекту и становится доступным для компиляции, выполнения
  или тестирования.

Например, импорт `org.example.model.User` сам по себе не подключает библиотеку
и не загружает её из интернета. Класс должен уже находиться среди исходников
проекта или в доступной зависимости.
