# Практическое задание

### Цель

Разработать консольное приложение на **Kotlin** по индивидуальному варианту, применив материал всех пяти глав лабораторной работы: базовый синтаксис, функции и лямбда-выражения, объектно-ориентированное программирование и коллекции, операции над коллекциями и extension-функции, `enum`, `sealed`, `data`-классы и делегаты.

## Общая постановка

Выберите вариант и реализуйте небольшую систему учёта для указанной предметной области. Программа должна хранить несколько объектов, выполнять над ними операции и формировать сводный отчёт.

Каждый вариант выполняется по единому техническому заданию. Различается только предметная область и названия полей, поэтому варианты имеют одинаковый объём и уровень сложности.

## Обязательные требования ко всем вариантам

### 1. Базовый синтаксис и управление выполнением

- Реализовать точку входа `main()`.
- Использовать ввод/вывод консоли (`readln()`, `print()`, `println()`); предусмотреть меню не менее чем из 4 команд.
- Использовать `val` и `var`, явные и выводимые типы, шаблонные строки.
- Применить арифметические, логические и сравнительные операторы.
- Использовать `if` и `when` (как минимум один из них — как выражение).
- Использовать диапазон и цикл (`for` или `while`) для демонстрации/обработки нескольких записей.
- Обработать ошибочный ввод или недопустимую операцию с помощью проверки и/или `try-catch`. Не допускать некорректных данных (например, отрицательной цены или количества).

### 2. Функции и лямбда-выражения

Создать не менее 4 функций, кроме `main()`:

- функцию создания/добавления записи;
- функцию поиска записи по идентификатору или имени;
- функцию расчёта показателя предметной области;
- функцию формирования отчёта.

Минимум одна функция должна иметь параметры по умолчанию или именованные аргументы. Минимум одна функция должна принимать функцию-параметр (лямбда/функциональный тип) и применять её к данным. Использовать лямбда-выражение для настройки фильтра, сортировки или расчёта.

### 3. Классы, наследование и коллекции

- Создать базовый `abstract class` или `open class` с общими свойствами и поведением.
- Создать не менее 2 производных классов, переопределяющих хотя бы один метод.
- Создать интерфейс с одним поведением и реализовать его в одном или нескольких классах.
- Использовать `data class` для сущности варианта.
- Хранить записи в изменяемой коллекции (`MutableList`); дополнительно использовать `Set` или `Map` для одной из задач (уникальные категории, поиск по ID, группировка).
- Продемонстрировать создание, изменение, удаление и поиск объектов.

### 4. Обработка коллекций и extension-функции

Реализовать и использовать собственную extension-функцию для типа из задания (например, `List<...>`), выполняющую полезную операцию.

В отчёте обязательно применить не менее 5 операций стандартной библиотеки коллекций из списка:

`filter`, `map`, `sortedBy`/`sortedByDescending`, `groupBy`, `distinctBy`, `sumOf`, `count`, `average`, `maxByOrNull`/`minByOrNull`.

Использовать цепочку минимум из 3 операций над коллекцией. Результат вывести пользователю.

### 5. Enum, sealed-классы и делегаты

- Создать `enum class` для статуса или категории записей (не менее 3 значений) и использовать его в логике программы.
- Создать `sealed class` или `sealed interface` для представления результата операции: например, успешный результат, ошибка валидации, отсутствие записи. Обработать варианты через исчерпывающий `when`.
- Использовать `data class` для объекта предметной области или результата.
- Реализовать делегированное свойство с `by`: собственный делегат или стандартный делегат (`lazy`, `observable`, `vetoable`, `Map`). Делегат должен применяться осмысленно, а не только для демонстрации синтаксиса.

### 6. Минимальный сценарий работы

Программа должна позволять пользователю:

1. Просмотреть начальный набор не менее 5 записей.
2. Добавить запись с проверкой корректности.
3. Найти запись по ключу.
4. Изменить статус или один из параметров записи.
5. Удалить запись (или отменить/закрыть её, если это соответствует предметной области).
6. Получить аналитический отчёт с фильтрацией, сортировкой и агрегированием.
7. Завершить работу через пункт меню.

Начальные данные задаются в коде. Ввод всех пяти записей вручную не требуется.

## Требования к равной сложности

Для всех вариантов необходимо реализовать один и тот же минимальный набор: 1 базовый класс, 2 наследника, 1 интерфейс, 1 `data class`, 1 `enum`, 1 `sealed`-тип, 1 делегированное свойство, 1 extension-функцию, 4 пользовательские функции, меню из 4+ команд и отчёт с цепочкой из 3+ операций коллекций.

Не добавляйте в отдельные варианты дополнительные обязательные технологии или более сложные алгоритмы. Дополнительные улучшения допускаются.
