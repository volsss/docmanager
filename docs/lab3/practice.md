# Практическое задание 3

Общие требования ко всем вариантам 

## Общие требования ко всем вариантам

Все перечисленные требования обязательны для каждого варианта.
Меняются только предметная область, названия полей и условие отбора.

1. **Опишите сущность через `data class`.** Используйте поля из своего варианта. 
В наборе должны быть строковое поле с названием объекта, поле категории, 
числовой показатель и логический признак. Заполните коллекцию минимум шестью 
объектами. Подберите значения так, чтобы категории повторялись, числовые 
показатели различались, а логический признак имел оба значения.

2. **Проверьте входные данные.** Добавьте блок `init` с `require`, проверяющий 
допустимость числового показателя. Используйте ограничения, соответствующие 
выбранной предметной области: например, цена, количество, длительность и число 
страниц не могут быть отрицательными; для рейтинга или средней оценки задайте 
разумный диапазон.

3. **Добавьте общее поведение.** Создайте интерфейс `Printable` с методом `printInfo()` 
и реализуйте его в классе сущности. Метод должен выводить краткую информацию об объекте.

4. **Организуйте хранение с инкапсуляцией.** Создайте класс-каталог или менеджер, 
который хранит объекты во внутреннем `MutableList`, объявленном как `private`. 
Реализуйте методы добавления и удаления объекта, а также получения всех записей 
через тип `List`. Добавьте свойство количества записей с `private set` и поддерживайте 
его актуальность.

5. **Продемонстрируйте наследование и полиморфизм.** Создайте базовый `open class` с 
открытым методом описания и два класса-наследника, один из которых переопределяет 
метод через `override`. Напишите функцию, принимающую объект базового типа, и вызовите 
её для обоих наследников. Этот короткий пример может быть отдельным от основной 
модели данных.

6. **Выполните отбор объектов.** Реализуйте именованную функцию-предикат для условия из 
варианта и передайте её в `filter` через ссылку на функцию, например 
`records.filter(::isSuitable)`. Выведите подходящие объекты.

7. **Постройте цепочку операций.** Сначала примените `filter`, затем `map`, чтобы получить 
из подходящих объектов строки или значения для отчёта. Результат выведите с помощью `forEach`.

8. **Используйте операции поиска и проверки.** Примените `find`, чтобы найти первый 
подходящий объект, и корректно обработайте ситуацию, когда результат равен `null`. 
С помощью any проверьте, есть ли хотя бы один объект с логическим признаком `true`; 
с помощью `all` — имеют ли все объекты этот признак; с помощью `count` посчитайте 
количество объектов, удовлетворяющих основному условию варианта.

9. **Вычислите статистику.** Найдите сумму и среднее значение числового показателя с 
помощью `sum()` и `average()`.

10. **Поработайте с `Set` и `Map`.** Получите `Set` уникальных категорий. Затем сформируйте 
MutableMap, в котором ключ — категория, а значение — количество объектов этой категории. 
Выведите пары ключ–значение, перебрав Map.

11. **Примените деструктуризацию.** Разберите один объект `data class` на локальные переменные.
При необходимости пропустите ненужный компонент с помощью `_`. Также переберите пары `Map` в 
форме `for ((category, count) in counts)`.

12. **Добавьте расширяющую функцию.** Создайте `extension function` для класса своей сущности, 
которая возвращает краткое текстовое описание объекта. Используйте её при формировании 
отчёта.

13. **Обработайте значения типа `Any`.** Создайте небольшой список `List<Any>`, включающий 
значения разных типов из своей модели, например строку, число и логическое значение. 
Обработайте его циклом с `when` и проверками `is`.

14. **Сравните типы коллекций.** Покажите, что для чтения данных достаточно `List`, а для 
добавления и удаления требуется `MutableList`. Не путайте `val`, запрещающий переприсваивать 
ссылку, с изменяемостью содержимого коллекции.
    
В конце программы выведите понятный отчёт: исходные записи, объекты, прошедшие отбор, 
уникальные категории, количество объектов в каждой категории, а также рассчитанную статистику. 
Для демонстрации методов коллекций используйте данные, на которых видны разные результаты, 
а не только одинаковые значения.
