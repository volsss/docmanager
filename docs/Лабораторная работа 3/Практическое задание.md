# Практическое задание

## Обязательные требования ко всем вариантам

Разработать небольшое консольное приложение на **Kotlin**, демонстрирующее работу с пакетами, многомодульной сборкой **Gradle** и корутинами.

Каждый студент выполняет один вариант.

### 1. Структура проекта

Создать Gradle-проект из трёх модулей:

```mermaid
treeView-beta
variant-project/
├── settings.gradle.kts
├── build.gradle.kts
├── core/
│   └── src/main/kotlin/
│       └── model/
├── service/
│   └── src/main/kotlin/
│       └── service/
└── app/
    └── src/main/kotlin/
        └── app/
```

Назначение модулей:

- `core` — модели предметной области;
- `service` — логика обработки данных;
- `app` — запуск приложения и вывод результатов.

Настроить зависимости между модулями так, чтобы `service` использовал `core`, а `app` использовал `service`.

### 2. Работа с пакетами

В модуле `core`:

- создать пакет `model`;
- описать data class для сущности своего варианта;
- определить не менее четырёх свойств сущности.

В модуле `service`:

- создать пакет `service`;
- реализовать класс для обработки коллекции объектов;
- использовать явные импорты классов из `core`.

В модуле `app`:

- создать пакет `app`;
- реализовать функцию `main`;
- создать тестовую коллекцию минимум из 10 объектов;
- передать коллекцию в сервис для обработки.

### 3. Работа с Gradle

В проекте необходимо:

1. Настроить многомодульную сборку через `settings.gradle.kts`.
2. Подключить необходимые Kotlin-плагины.
3. Добавить зависимость `kotlinx-coroutines-core`.
4. Настроить запуск приложения через Gradle.
5. Создать собственную задачу Gradle с именем `analyzeData`.
6. В задаче `analyzeData` вывести название варианта и сообщение о завершении анализа.
7. Продемонстрировать выполнение задач `projects`, `tasks`, `build` и `run`.

В корневом `build.gradle.kts` или соответствующем модуле продемонстрировать регистрацию пользовательской задачи с помощью `tasks.register`.

### 4. Асинхронная обработка

В сервисе реализовать три suspend-функции:

- `loadData()` — имитирует получение исходных данных с помощью `delay()`;
- `processData()` — выполняет обработку данных согласно варианту;
- `generateReport()` — формирует итоговый отчёт.

Использовать:

- `runBlocking` для запуска приложения;
- `launch` для запуска одной операции без возвращаемого результата;
- `async` и `await` для получения результатов двух независимых вычислений;
- `coroutineScope` для организации совместной работы корутин.

Продемонстрировать, что две независимые операции выполняются конкурентно, а итоговый отчёт формируется после получения обоих результатов.

### 5. Результат выполнения

Программа должна выводить:

- название предметной области;
- количество обработанных объектов;
- результат первой операции;
- результат второй операции;
- итоговый отчёт.

Для демонстрации асинхронности добавить небольшие задержки в операции и показать порядок сообщений в консоли.

## Индивидуальные варианты

Во всех вариантах сохраняются одинаковые требования из общего задания. Отличаются только предметная область, поля сущности и конкретные операции анализа.

Для каждого варианта требуется создать соответствующую модель и реализовать две независимые операции обработки данных.

Варианты рассчитаны на одинаковый объём реализации: одна модель, коллекция из 10 объектов, две операции анализа и один итоговый отчёт.

Модель `Student`: фамилия, группа, возраст, средний балл.

1) Найти средний балл студентов группы. 
2) Определить количество студентов с баллом выше заданного значения.

2) Подсчитать книги, изданные после заданного года.

## Требования

Для всех вариантов необходимо реализовать:

- ровно 3 Gradle-модуля;
- одна основная модель с 4 полями;
- 10 исходных объектов;
- ровно 2 аналитические операции;
- 3 suspend-функции;
- 2 независимых вычисления через `async`;
- 1 пользовательская Gradle-задача.
