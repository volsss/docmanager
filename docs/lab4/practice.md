#  Практическое задание 4

## Общие требования к выполнению

Для своего варианта необходимо разработать консольную программу на **Kotlin**. 
Сторонние библиотеки не требуются.

### 1. Класс и перечисление

Создайте `data class` для сущности из своего варианта. Используйте указанные поля. 
Создайте `enum class` для её состояния минимум с тремя значениями. Выведите список 
состояний и с помощью `when` подготовьте для каждого состояния короткое текстовое 
описание.

### 2. Работа с коллекцией

Создайте список минимум из пяти объектов. Выведите исходный список, затем с 
помощью `filter` отберите объекты по условию из своего варианта. Используйте 
хотя бы ещё одну операцию из следующих: `map`, `find`, `count`, `sum` или `average`. 
Результаты должны выводиться в понятном виде.

### 3. Простой sealed-тип

Опишите результат поиска с помощью `sealed`-типа, например `SearchResult`, у которого 
есть два варианта: найденная запись и сообщение о том, что запись не найдена. 
Реализуйте поиск одной записи и обработайте оба результата через `when`.

### 4. Обобщённый класс и функция

Создайте простой класс `Box<T>`, который хранит одно значение типа `T`. Создайте 
обобщённую функцию `identity(value: T): T`, возвращающую переданное значение. 
Покажите их работу как минимум с двумя типами, например `String` и `Int`.

### 5. Объекты Kotlin

Создайте `object` с функцией для вывода служебных сообщений, например 
`AppLogger.log(message)`. В классе своей сущности добавьте `companion object` с одной 
константой и простой функцией `create(...)`, создающей объект. Продемонстрируйте 
их вызов.

### 6. Перегрузка оператора

Создайте небольшой вспомогательный класс `Counter` с числовым свойством `value: Int`. 
Перегрузите оператор `plus`, чтобы выражение `Counter(2) + Counter(3)` возвращало новый 
`Counter` со значением `5`. Выведите результат.

### 7. Отложенная инициализация

Добавьте свойство `summary` с `by lazy`, которое формирует короткое текстовое описание 
данных программы. Обратитесь к свойству дважды и выведите полученное значение.

## Варианты заданий

Во всех вариантах необходимо выполнить все общие требования из предыдущего раздела. 
Вариант задаёт предметную область, состав полей, состояния, условие фильтрации и 
числовую характеристику для анализа. Добавьте не менее пяти исходных записей, 
в том числе записи, которые проходят фильтр и не проходят его.

> **Примечание:** используйте не менее пяти записей. Подберите данные так, чтобы
> некоторые записи проходили условие фильтрации, а некоторые — нет. Если порог
> в варианте не указан явно, выберите его самостоятельно и укажите в отчёте.
